# Build scope and limits

The original export has no package manifest or framework version declaration. We supplied a local validation harness using locked Svelte 5.57.3, mdsvex 0.12.8, SvelteKit 2.70.3, Vite 7.3.7, plugin-svelte 6.2.4 and adapter-static 3.0.10, with TypeScript 5.9.3 and esbuild 0.28.2. It is a tested reconstruction of missing build infrastructure, not a claim about the support desk's original build command.

The single-page renderer expands the exported eager tenant glob explicitly. The complete site uses Vite's native tenant and page globs and SvelteKit static prerendering. Both pipelines agree on the rendered page's stable content, counts and generated reference. Full-site output supplies the original companion routes and index.

The 2026-10-29 npm audit returned six low-severity package findings (no moderate/high/critical findings): SvelteKit, adapter-static, plugin-svelte, its inspector, cookie and deepmerge. They include form redirect/cache-header behavior and transitive dependency findings. These are disclosed local toolchain findings, not a claim of a demonstrated exploit in this static exercise. No enhanced form, authentication, server API, untrusted remote render data or public server was configured. Do not treat the harness as a security-audited production application. Fixing them through major-version migrations would be separate toolchain work and would require renewed validation; no forced audit upgrade was performed.

A page render is a dated snapshot. The supplied layout computes elapsed days during rendering/hydration and has no continual clock update. Byte-for-byte HTML equality is not guaranteed across dates, environments or build-path-dependent compiler IDs. The manifest protects this reviewed output; rebuild comparisons should also inspect source identity, visible counts, signature, index links, interactions and console errors.

Original helpers deliberately remain unchanged. Synthetic tests expose boundaries outside the actual input: conflicting IDs use the last row, malformed timestamps/metadata are not robustly validated, prototype-named tags can break aggregation, an empty timeline can emit NaN, and whitespace-only signatures generate references. The actual frozen data passes schema checks, contains only exact duplicate payloads and supported tag values, and the actual signature is nonblank. These tests define limitations; a test that successfully demonstrates an unsafe boundary is not a claim that the helper handles arbitrary future data safely.

The manifest and deterministic desk reference provide reproducibility and local integrity, not third-party authentication or proof of the course's hidden evaluator. No attempt was made to query that evaluator.

The revised allocator rejects conflicting records and ignores JSON object key order when comparing duplicates. It applies the desk-note list before the original classifier; it does not detect symptoms in new report bodies automatically. Human body review supports the current snapshot. Missing future note entries require renewed review. Conflict checks are conservative across the entire input export, including any other tickets.
